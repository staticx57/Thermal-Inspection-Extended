# Optional: ML Depth Estimation (for Parallax Compensation - NEW v3.3.0)
# ============================================================================
# Uncomment to enable DepthAnything V2 depth estimation for improved parallax
# compensation accuracy. This provides state-of-the-art monocular depth estimation
# for better thermal-RGB alignment. torch is also used (if installed) to
# GPU-accelerate the laplacian_pyramid fusion mode - see
# FusionProcessor._laplacian_pyramid_gpu; without it, that mode still works,
# falling back to CPU (optionally at reduced internal resolution - see
# FusionProcessor.laplacian_cpu_scale).
#
# torch>=2.0.0              # PyTorch (CPU version, ~2GB download)
# transformers>=4.30.0      # Hugging Face Transformers
# huggingface-hub>=0.16.0   # Model downloads and caching
#
# For GPU acceleration (recommended for real-time performance, NVIDIA only -
# see the AMD/DirectML note below):
# Install a CUDA build of PyTorch instead of the default CPU-only wheel.
# Pick the cuXXX tag matching your driver from https://pytorch.org/get-started/locally/
# (anything <= your driver's max CUDA version works - drivers are backward
# compatible). Example, verified working with an RTX 4000 Ada on Windows:
#   pip install torch --index-url https://download.pytorch.org/whl/cu126
#
# IMPORTANT (Windows only): if you already have PyQt6 installed, importing
# it BEFORE torch in the same process corrupts Windows' DLL search order
# for a CUDA-enabled torch build - torch.cuda.is_available() silently
# returns False, or torch itself fails to import with "WinError 1114 ...
# c10.dll". Order-dependent; importing torch first avoids it entirely.
# thermal_inspection/__init__.py already does an early best-effort
# `import torch` for exactly this reason - don't remove it, and if you're
# probing torch/CUDA from a standalone script, import torch before PyQt6
# there too.
#
# AMD/Intel GPUs on Windows have no CUDA path. The realistic route is
# DirectML (`pip install torch-directml`) - as of 2026-09, thermal_inspection
# has a full "directml" device option wired end to end (settings panel ->
# app.set_device() -> every torch GPU resolver, see
# thermal_inspection/utils/gpu_device.py) for the 4 raw-torch-tensor GPU
# paths (fusion_processor.py's feature_weighted/laplacian_pyramid,
# fusion_3d_panel.py's relief/normals, parallax_compensator.py's remap) -
# this code is UNVERIFIED on real Intel/AMD hardware (none available in
# the environment it was built in) and NOT ACTIVE until torch-directml is
# actually installed, which is not done automatically because of a real
# version conflict: torch-directml's latest published release (checked
# 2026-09-09 via PyPI) hard-pins torch==2.4.1/torchvision==0.19.1 exactly,
# and this project's CUDA-verified environment runs a newer torch -
# installing it as-is would downgrade torch and risk every existing CUDA
# path. Confirm current torch-directml/torch compatibility before
# installing, on a machine that actually has an Intel/AMD GPU to verify
# against.
#
# parallax_compensator.py's depth-estimation model (MiDaS/DepthAnything,
# via HuggingFace's pipeline()) is the ONE path DirectML does NOT cover -
# pipeline(device=...) only accepts a CUDA device index or -1/CPU, not a
# DirectML device object, so a "directml" device request there silently
# falls back to CPU (same as an explicit "cpu" request) rather than
# raising. Using DirectML there for real would mean loading the model
# manually and moving it with .to() instead of the pipeline() convenience
# API - not implemented, still no AMD/DirectML hardware to verify against.
#
# Model Downloads (automatic on first use):
#   - Small model: ~100MB (good for CPU, 24.8M params)
#   - Base model: ~200MB (balanced, 97.5M params)
#   - Large model: ~350MB (best accuracy, GPU recommended, 335M params)
#
# Without these dependencies, parallax compensation uses simplified geometric mode.

# ============================================================================
# Optional: Intel RealSense (Depth + Color, D400/L500 series) - NEW
# ============================================================================
# Uncomment to enable Intel RealSense support: real (not estimated) depth for
# parallax correction ("Intel RealSense" depth method in the Parallax tab)
# and the 3D Fusion tab's live point-cloud view. Works generically across
# D415/D435/D435i/D455/D457/L515 - stream profiles aren't hardcoded to any
# one model. T265 (tracking-only, no depth/color stream) is detected but
# reported unsupported - nothing in this app uses pose/SLAM data.
#
# pyrealsense2>=2.54.0        # Intel librealsense Python bindings - D400 series ONLY
#
# L515 (L500-series LiDAR) users: DO NOT use the pin above. Confirmed live
# 2026-09-18: librealsense/pyrealsense2 v2.55.0+ permanently dropped L515
# enumeration on Windows (upstream EOL removal, not a bug - see
# https://github.com/realsenseai/librealsense/issues/12960) and PyPI no
# longer publishes any pre-2.55 wheel at all, for any Python version. The
# only working path is building pyrealsense2 from source at the last
# L515-supporting tag (v2.54.2) against your own Python - automated by
# scripts/install_realsense_l515.ps1 (Windows; run
# `scripts\install_windows.bat --with-realsense-l515`, or the script
# directly). D400-series cameras are unaffected either way and should just
# use the pip pin above.
#
# IMU (gyro + accelerometer): the L515 and D435i/D455/D456 expose one (Bosch BMI085/BMI055, +-4 g, +-1000 deg/s). 3D
# Mapping uses it as a rotation head-start and a gravity check; cameras without one (plain D435, D415) just skip it.
# No RealSense camera does ICP/tracking in hardware - that runs in Open3D on the PC.
#
# The 3D Fusion tab AND the 3D Mapping world viewer additionally need PyOpenGL for pyqtgraph's GLViewWidget
# (real-time rotatable point-cloud rendering) - without it they show a "PyOpenGL not installed" placeholder instead of
# crashing. (Verified with PyOpenGL 3.1.10.) It is a small pure-Python wheel and both 3D tabs are headline features,
# so it is installed by default (it used to be commented out, so a fresh install had no 3D views).
PyOpenGL>=3.1.0
# PyOpenGL_accelerate>=3.1.0  # optional, faster PyOpenGL - needs a C compiler to build

# ============================================================================
# Troubleshooting
# ============================================================================
#
# Import errors after install:
#   - Restart terminal/IDE
#   - Check Python version: python --version
#   - Verify installation: pip list | grep [package]
#
# PyQt6 issues:
#   - Windows: pip install --upgrade PyQt6
#   - Linux: pip install --upgrade PyQt6
#
# Serial port access denied:
#   - Windows: Check Device Manager for COM port
#   - Linux: sudo usermod -a -G dialout $USER (logout/login required)
#
# Camera not detected:
#   - Check camera connections
#   - Windows: Check Device Manager
#   - Linux: ls /dev/video* or v4l2-ctl --list-devices
#
